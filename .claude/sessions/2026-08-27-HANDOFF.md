### Load-bearing facts (verified this session)
- **Decode = server-side PHP.** `includes/propresenter7_decode.php` — a hand-rolled proto3
  wire-walker (browser can't decode: static module is `--no-decode`, reflection is CSP-blocked).
  Field tables byte-verified against `manage/editor/protos/proto-7.16/*.proto` + a CI lockstep guard.
- **RTF has TWO dialects PP7 itself writes** — Mac `\cocoartf` (soft-return) + **Windows `\rtf0`**
  (`\par`, `\csgenericrgb`). Import parses both (extended the shared `_bulkImport_rtfToText`, which
  also fixed latent cp1252 mojibake in the existing Pro6/EasyWorship/Proclaim importers). A
  dominant-font gate drops small copyright/attribution runs so they don't pollute lyrics (caught a
  real `',`-pollution false-positive mid-build).
- **`.probundle` = ZIP64 with a broken EOCD** (98-byte central-dir overstatement) that `ZipArchive`
  /`unzip`/`zipfile` ALL reject (code 21). `includes/propresenter7_zip.php` never reads the EOCD —
  scans local headers, resolves `0xFFFFFFFF` ZIP64 sentinels. **Proven on the owner's real 2 MB
  bundle** (in `_temp`/scratchpad, uncommittable — copyright + size).
- **Genuine `.probundle` layout** = `.pro`(s) at ROOT + media under absolute path, NO manifest (the
  inner `.pro` IS the manifest). The exporter's old invented `Documents/`+`manifest.json` is fixed.
- **Cross-platform (owner's Q):** the `.pro` protobuf is identical Mac/Windows; Cocoa RTF is the
  cross-platform-safe export dialect (Windows PP must read Mac files). A real **Windows-authored**
  fixture (ChrisMBarr `v7-feature-test-win.pro`, PP 7.13.2/Win) covers Windows import. The one
  residual: a real Windows-PP *open of our export* (owner checklist, non-blocking).
