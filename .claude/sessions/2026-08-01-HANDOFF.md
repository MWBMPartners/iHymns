## What the D12/D1 discipline actually caught

This wasn't a paper exercise — building the stub-gateway e2e suite (commit 5) surfaced two real bugs
that static reasoning alone would not have found:

1. **The single-flight lock was held for its full 10s window regardless of actual fetch duration**,
   so `intappsForceRefresh()` ("Refresh now") reported "another refresh in flight" for up to 10s
   after the PREVIOUS call had already finished. Fixed: `RefreshLockedUntil = NULL` on both the
   success and failure commit branches.
2. **`CURLOPT_MAXFILESIZE` fires via its own error path (`CURLE_FILESIZE_EXCEEDED`) before the
   manual write-callback's oversized flag is ever consulted** — verified empirically with a
   standalone repro. Previously an oversized response silently fell through to generic `unreachable`
   with no error code at all. Fixed: both triggers now map to the same `OVERSIZED` outcome.

And the D1 pre-launch BLOCKER (enabled-but-un-migrated `tblIntAppsSync` throwing under mysqli STRICT
on the public home page) was not just fixed — it was **reproduced live**: removed the guard, hit
`app_status` with the module enabled and the table renamed away, got a real HTTP 500 with the exact
`mysqli_sql_exception` in the server log; restored the guard, same request returned 200 with a
graceful degrade to compiled defaults.
