## Root cause (verified, corroborated by the symptom itself)

`appWeb/public_html/manage/.htaccess:54-56` 301-redirects the `.php` form of EVERY `/manage` URL to its
extensionless sibling for cosmetic URL-hiding, with **no method guard**. A browser replays a 301'd
POST/PUT/PATCH/DELETE as a **body-less GET** (only 307/308 preserve method+body — RFC 7231 §6.4). So every
browser POST to a literal `/manage/**.php` reached PHP with `$body = []`:
- v2 editor metadata saves + the WHOLE arrangement editor (empty `songId` → 400),
- server-PDF download, bulk import, activity-log geo, place/city upsert.

Reads (GET) survive the redirect (query preserved), so the song loaded fully and it masqueraded as a
client bug — `#1846`/`#1847`/`#1851` were downstream symptom-chasing. v1's editor was immune: it already
posts to the extensionless `/manage/editor/api2` (`editor/index.php:1719`). The user seeing the server's
own 400 text proves the request reached `api2.php` as a GET with an empty body.
