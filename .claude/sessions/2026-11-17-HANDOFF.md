**The CVE-2026-111497 review (#2157)** is the one new piece of work. In plain words: Brotli is a way of
compressing web data. A flaw in Google's Brotli *decoder* (the part that unpacks it) lets deliberately
broken data crash a program or, at worst, run an attacker's code. It only matters where something
unpacks Brotli data an attacker controls. Attackers are using it (CISA listed it on 27 October; its
10 November deadline for US federal agencies has now passed). A first look while filing found: the live
site does not unpack Brotli; the PHP importers (`CURLOPT_ENCODING` set to `''`) and the PowerShell
importer (asks for `br`) may unpack it, on the owner's computers; Node.js in CI follows the newest 22.x
and has no Brotli npm package; the Apple and Android apps still need checking. **Nothing has been
verified, and the issue's facts come from search summaries**, because this session's network blocked the
CVE record and the vendors' pages. The first step is to read those directly (Node.js fixed versions
22.23.4 / 24.22.1 / 26.12.1; Brotli fixed 1.0.10 / 1.1.1 / 1.2.1). If anything is exposed, report it in
a **private** GitHub security advisory, not the public issue (`SECURITY.md`).

## Traps — read before repeating any of this work

1. **A search pattern that matches more than you meant gives a false count.** Look at a sample of the hits.
2. **On the Mac, the Bash tool runs zsh, not bash.** Use `${C}`, or run a script file with `bash`.
3. **The working-branch check is binding.** Whatever the §2 command lists IS the working branch.
   `archive/*` is excluded.
4. **Pull requests our workflows open with the automatic GitHub token have their checks held for
   approval (#2127).** A person's approval, or a push of a real change to the branch, starts them. Re-run
   requests from a cloud session are refused (403), and an empty commit or a close-and-reopen is against
   the rules. Dependabot pull requests are not affected.
5. **The automatic merge does not delete the branch.** Delete it by hand, after an empty tree diff.
6. **"Closes #N" in a pull request to `alpha` does not close the issue.** Close it by hand.
7. **Apple builds need `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`**, or `swiftlint` fails
   silently and `swift test` runs nothing. The Xcode licence must also be accepted.
8. **An empty review is not a clean review.** Check the error output and the size of the review file.
9. **A Node script that calls `process.exit()` can lose the end of its output into a pipe.** Write to a file.
10. **Before switching branches, check the target does not track `_temp/`, the session logs or the
    database dump** (#2108).
11. **Read clock times from a clock.** Do not guess them.
12. **Apple's design-guidelines page returned only its title when fetched.**
13. **Cloud sessions cannot change the Mac.** Anything under `~` written in a cloud session disappears
    when it ends. Computer-wide changes go through `tools/install-device-rules.sh`, run on the Mac.
14. **New: there are two wikis, and a cloud session can only change one.** The repo's `wiki/` folder is
    the maintained copy and can be pushed. The GitHub wiki (`iHymns.wiki`) is a separate repository that
    the git proxy refuses, so it falls behind until someone copies `wiki/` across by hand. Edit `wiki/`,
    never the GitHub wiki clone, and do not treat the GitHub wiki as current.
15. **New: the `gh` command's token is invalid in cloud sessions.** Use the GitHub tools. They can edit
    an issue's milestone and labels, but cannot edit a milestone itself or the Project board.
16. **New: blocked sites look like "refused" or "not found".** In this environment the CVE sites, NVD, OSV
    and several security blogs are blocked by the network rules. Web search still works. The owner can
    allow hosts under Network access in the cloud environment's settings.
17. **New: a version commit refused by the branch rules is a warning, not a failure.** "Failed to push
    version bump after 5 attempts" means #2143 again. The deploy itself is fine.
