## Shape of the change

`/sitemap.xml` is now a **sitemap index** (same URL). Children — `static`, `songbooks`, `songs`
(paginated at 10,000/page, owner decision D7), `musicians`, `themes`, `works`, `publishers`
(`IsActive=1` only, D6), `tunes` (all registry rows, D5) — are served by the SAME file via
`?section=&page=`, routed by a new `.htaccess` rule to `/sitemap-<section>[-<page>].xml`.

Every entity's `<lastmod>` now comes from its own `UpdatedAt` (omitted, never invented, when unknown).
Conditional GET (ETag/Last-Modified/304) runs off cheap per-table `(COUNT, MAX(UpdatedAt))` aggregates,
computed once per request and reused for the index's own per-child dates (one mechanism, two consumers).
The old per-songbook `SongData::getSongs($bookId)` bulk-record read is gone — songs are now a slim
`SongId + UpdatedAt` query with a bound `LIMIT`/`OFFSET`. Host resolution now calls the shared
`appCanonicalHost()` instead of a second hardcoded host array. `/favorites` and `/settings` were removed
(D2); `/stats` was never added (D3); `/work/`, `/publisher/`, `/tune/`, `/whats-new`, `/request` were added
(previously missing). `robots.txt`'s `alpha.ihymns.app` → `dev.ihymns.app` (D4, the real hostname).

## One deliberate plan deviation, corrected against the real schema

The plan's §2 table claimed `tblWorkSongs` has an `UpdatedAt` column ("GREATEST(w.UpdatedAt, MAX(tblWorkSongs.UpdatedAt))").
Checked `appWeb/.sql/schema.sql` — that table has only `CreatedAt`, no `UpdatedAt`. Implemented with
`CreatedAt` instead (documented inline in `sitemapFingerprintAggregates()`'s and `sitemapSectionWorks()`'s
doc-blocks: it still catches a song being added to/removed from a Work, just not an in-place edit of an
existing membership row's own `Note`). A real, small, understood gap — not a blocker.

### What shipped

A new "Search engine visibility" card on `/manage/configuration` — three switches (Production /
Beta / Alpha-dev). Switching a channel OFF is a full search-engine hide made of three pieces, all
reading through ONE stored `tblAppSettings` row (`search_visibility_channels`, CSV of the VISIBLE
channels — the `webhooks_enabled_channels`/`intappsapi_enabled_channels` storage precedent) and ONE
helper (new `includes/search_visibility.php`): (1) `X-Robots-Tag: noindex` on every response (`index.php`
also emits the matching `<meta name="robots">`; wired on `index.php`, `api.php`, `og-image.php`,
`qr.php`, `org-logo.php`, `song-media.php`, `audio-media.php`); (2) `/sitemap.xml` (+ every child) 404s,
gated ahead of the DB fingerprint work and conditional GET; (3) `robots.txt` — now dynamic
(`robots.txt.php`, the static file deleted) — drops that channel's `Sitemap:` line and, fixing a wart
along the way, now advertises only its OWN sitemap host via `appCanonicalHost()` instead of all three
channels' hosts on every channel. **Deliberately never adds `Disallow: /`** — a blocked crawler can
never see the noindex signal, so staying crawlable is what makes noindex actually work; the new guard
actively bans a bare `Disallow: /` from ever appearing.

**Locked defaults (no admin action, no DB migration — confirmed not needed, rule #19 applies to
tables/columns, not rows in an existing key/value table):** production listed, beta hidden, alpha
(dev) hidden. Absent setting = code constant `'production'`. "All hidden" stores the sentinel `'none'`
(not `''`, which `setAppSetting()`'s own convention reads as "unset").

`includes/environment.php` gained the extracted, shared `ihymns_parse_channels_csv()` (rule #22 —
`webhookParseChannelsCsv()` in `includes/webhooks.php` is now a one-line delegate to it, same
name/signature/behaviour). `save_search_visibility` mapped `web_only:configuration-secrets` in
`test-manage-action-api-coverage.php` (rule #48) — no API twin; a whole-installation SEO switch has
no native-app use case.
