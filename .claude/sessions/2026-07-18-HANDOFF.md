## PR-14 (#1425) — optional Service-Mode mirror (LAN TV state → `service_broadcast`, mirror-on-ack) — DONE 2026-07-18 (un-PR'd)

**Owner directed "resume with option B" — start PR-14 now**, accepting the interim un-merged-PR-11 state.

**Base = `alpha`, NOT the PR-11 branch.** PR-14 is INDEPENDENT of PR-11 (the watch relay): it wires the *operator's phone/
iPad LAN remote* (`RemoteControlCoordinator`, PR-7) to mirror the TV's canonical state to the server via the EXISTING
`service_broadcast` (PR-10's native Service-Mode client + `APIClient`), so basing off `alpha` keeps the two PRs
independent and side-steps the stacking/merge-race the owner wants to avoid. Branch: `feat/apple-p2-pr14-service-mirror`.

**Scope (strategy §2.4.1; issue #1425 — small, "Haiku", 0.5d, NO new backend):** the tvOS app owns the one canonical
`(songId, componentIndex, lineIndex, displayState)`; a LAN command changes it. When the venue ALSO runs a Service session
for remote congregants, the operator's remote **mirrors state to the server via `service_broadcast` (mirror-on-ack, ONE
writer)** so congregants sync. LAN link never carries congregant traffic; server never carries TV control. Native-only
win: an internet outage doesn't kill the local projection — only the congregant mirror degrades.

**Resolved design (built):** the mirror observer is a new `@MainActor @Observable` `ServiceMirrorController` (IHFeatures)
with an INJECTED broadcast closure — it taps `RemoteControlCoordinator.apply()`'s `.controlling` state (the TV's
echoed/acked canonical state, so mirror-on-ack = mirror per `.controlling`, deduped on `songId|componentIndex|displayState`,
lineIndex/revision excluded). It never touches `ServiceModeEngine`/`RemoteControlSession`/`RemoteSessionActor`/IHRP.
**The crux (F-1):** `service_broadcast` REQUIRES a client `sessionId` and there is NO API to discover it (the web console
resolves it in-page) — so, under "no new backend," the operator **types the session number** into the OFF-by-default,
signed-in-gated `ServiceMirrorCard` (forced by the constraint). One writer = only the operator's signed-in device with the
card armed; server re-checks `serviceMode_userCanOperate` per call. Dormant/opt-in; failures never disrupt LAN control
(401/403/404 stop with a notice; else degrade + one retry). `frozen→live` display translation.
