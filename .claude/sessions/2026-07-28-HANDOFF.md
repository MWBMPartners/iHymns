```sql
SELECT sc.SongId, sc.Id AS ComponentId, sc.SortOrder, sc.Type, sc.Number,
       JSON_LENGTH(sc.LinesJson) AS jsonLines, COUNT(ll.Id) AS mirrorLines
  FROM tblSongComponents sc
  LEFT JOIN tblLyricLines ll ON ll.ComponentId = sc.Id
 GROUP BY sc.Id
HAVING jsonLines <> mirrorLines
 ORDER BY sc.SongId, sc.SortOrder;
```

`mirrorLines = 0` ⇒ the component-count branch; anything else ⇒ the per-component line-count branch.

**The judgement to make once it's named:** one-off legacy row vs. a live writer bug. The mirror has
a single write funnel (`lyricLinesWriteComponents()`, rule #25), so a systematic bug would not
produce exactly one — but confirm rather than assume. A one-off is repairable; a writer bug is not,
and at this resolution the two look identical.

### 1. #1649 — setlist data loss (HIGHEST — active, silent, permanent)

Client pushes all setlists → server truncates to 50 (`api.php:2898`) → replace-mode **deletes every

pass entirely**. Absence only means intent when the payload is complete. Also cap + warn client-side

per-row `UpdatedAt` and never consults it.

## 🧭 The method that finally worked — use it

`.claude/standing-tasks.md` **§2b**. An **issue-verification sweep** ("are our filed issues
accurate?") is bounded by what someone already noticed and **structurally cannot find an unfiled
bug** — that is why months of sweeps missed everything found today. A **behaviour audit** ("does the
code do what it claims?") found **20+ real defects incl. 3 security issues in one afternoon**.

write-path integrity · orphan detection · constraint-vs-intent · cross-surface consistency ·

# 🔒 DURABLE CONSTRAINTS

- **Three docroots, ONE MySQL.** `dev` / `beta` / `www` share a single database. A dropped column
  vanishes for all three at once, and mysqli runs STRICT so an ungated read **throws** rather than
  degrading.

  the whole "Apply all" mechanism. `deploy.yml:214`'s change detection uses a fixed five-commit

# 🧠 LESSONS THAT COST SOMETHING

**The version bump is not cosmetic.** `version-bump.yml` fires on pushes to `beta` and `alpha`, but
a hand-merged batch can still land without one. `infoAppVer.php` drives the `?v=` cache-busters
**and** the service-worker cache version (#81) — so a client holding the old SW cache keeps serving
the pre-fix bundle. That is precisely the "looks alive, does nothing" failure of #1565. **Check the
version moved after any large alpha batch.**

**`git add <paths>` does NOT clear a pre-existing index.** Twice a commit swept in another agent's
work; the second time, 207,000 lines of `songs.json` deletion landed inside the join-codes commit.
**While agents are running: `git diff --cached --name-only` FIRST**, and `git restore --staged`
anything that isn't yours. Otherwise a revert of one change silently undoes an unrelated one.

**Verify an agent's finding before acting on it.** Several were subtly wrong in detail while right in
conclusion — a "hardcoded 5-tier list" that didn't exist, a "10 gates" count that was nine. The
conclusions held; the specifics didn't. Checking cost one grep each time.
