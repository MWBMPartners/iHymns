## What the D12/D1 discipline actually caught

This wasn't a paper exercise — building the stub-gateway e2e suite (commit 5) surfaced two real bugs
that static reasoning alone would not have found:

1. **The single-flight lock was held for its full 10s window regardless of actual fetch duration**,
   so `intappsForceRefresh()` ("Refresh now") reported "another refresh in flight" for up to 10s
   after the PREVIOUS call had already finished. Fixed: `RefreshLockedUntil = NULL` on both the
   success and failure commit branches.
2. **`CURLOPT_MAXFILESIZE` fires via its own error path (`CURLE_FILESIZE_EXCEEDED`) before the
   manual write-callback's oversized flag is ever consulted** — verified empirically with a
   standalone repro. Previously an oversized response silently fell through to generic `unreachable`
   with no error code at all. Fixed: both triggers now map to the same `OVERSIZED` outcome.

And the D1 pre-launch BLOCKER (enabled-but-un-migrated `tblIntAppsSync` throwing under mysqli STRICT

## 🔴 #1735 — OFFLINE DOWNLOAD WAS 100% DEAD ON PRODUCTION CONFIG. **FIXED, `b1376004`.**

The API contract probe's headline find, reproduced and fixed the same session.

`GET /api?action=bulk_songs&songbook=…` returned **HTTP 500 whenever
`content_gating_enabled='0'` — the DEFAULT, i.e. production.** It is the only
endpoint serving the offline songbook bundle, so "Download songbook for offline"
had been completely non-functional for every PWA and native client since
`3adc4875` (2026-07-07), about four weeks.

**The cause is exactly backwards from its own comment.** `api.php:1817` called
`contentGatingEnabled()` unconditionally to pick a `Cache-Control` value, under a
comment promising the header is a *"NO-OP (stays `public`) while
content_gating_enabled=0"*. That function lives in `includes/content_gating.php`,
and every `require_once` of it in `api.php` is either inside a **different** case
block (917/1094/1217) or **below** this line (1893); `pages/song.php` loads it
only inside `if (content_gating_enabled === '1')`. With gating OFF nothing had
loaded it → fatal.

> **A dormant feature is supposed to make a caller do nothing. Here, being
> dormant is what made the caller crash — and ONLY when dormant**, which is
> precisely why every gating-enabled test environment looked healthy.

Toggle proof: `'0'` → 500/60 bytes; `'1'` → 200/147,902 bytes. After the fix:
`'0'` → 200 + `Cache-Control: public`, `'1'` → 200 + `private`. **So #1386's
actual security intent — mark the per-tier bundle `private` so a shared cache
can't serve one tier's render to another user — executed for the first time in
this commit.** It never had; the only path that would run it died first.

⚠️ **This lands inside #1597's territory** ("offline download's 7 defects —
FIXED"). Those fixes were real. The endpoint simply was never exercised against
a *default-configured* install afterwards, so the feature stayed dead from a

### 🧭 THE METHOD LESSON OF THIS PROGRAMME — read this before writing another guard

Four consecutive rounds ended with a guard **green while the thing it guarded was broken**. The
root cause is now unmistakable and it is not carelessness:

> **Source inspection was used as the primary evidence for properties that have a runtime handle.**

Whether a predicate returns true for a *wrapped* 1213, whether a gate's polarity is right, whether a
probe is the strict one — those are **behaviours**. Pattern-matching source for them yields an
assertion about the file's *vocabulary*, and vocabulary survives any mutation that keeps the words.

The worked example is `songRelocateIsTransactionFatal()`. Guarded three ways:
1. **Inline per catch** → the rule held in one function while ELEVEN catch blocks between the
   relocate and `commit()` still swallowed. Reach was wrong.
2. **Extracted + source-inspected** (call sites mention the predicate; its body mentions `1213`,
   `1205`, `mysqli_sql_exception`) → a reviewer replaced the body with `return false;`, left the
   vocabulary in a dead `$fatalCodes` array, and the **whole suite stayed green** while every site
   resumed swallowing. Reach fixed; the reached thing unpinned.
3. **`tests/php/test-transaction-fatal.php`** — constructs exceptions, asserts the returned
   booleans, reads no source. A predicate cannot pass by CONTAINING the right words, only by
   ANSWERING correctly.

**Proof, run against the real tree:** with the body gutted,
`test-song-relocate-hardening.php` stays **GREEN** and `test-transaction-fatal.php` goes **RED**.

**The rule: when a property lives in a PURE function, test the function.** Reserve source inspection
for what has no runtime handle — "every call site does X", "no fragment carries an inline script",
"no page hardcodes a CDN version". That is what `test-song-relocate-funnels.php` and
`test-fragment-inline-scripts.php` do, and it is the right tool for that job.

⚠️ Also learned the hard way in 4c: **a remediation can introduce the bug it is removing.**
`songRedirectsTableReady($db, true)` (added by the same pass) wraps its cause in a plain
`RuntimeException`, and the predicate only type-checked the OUTERMOST exception — so a deadlock
inside that probe was swallowed again, through a brand-new code path added by its own fix. Six
guard holes remain, tracked on **#1691**; the code they guard is currently correct.
