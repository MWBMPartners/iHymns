## What the owner asked

Add support for Apple's folding iPhone ("iPhone Duo") to the Apple app — use the wider screen when it
is fully open, and behave well closed. Then: file it as GitHub issues with enough detail to work from,
accepting that Apple's documentation is thin because most of it is "coming later this month".

## What was established, and how sure we are

**Confirmed from Apple's own pages** (Newsroom, developer.apple.com/iphone-duo, tech-talk pages):
5.4-inch closed, 7.6-inch open, same aspect ratio on both, ships with iOS 27.1, on sale 23 October
2026. Apps run without recompiling but "screen usage improves with each SDK". Apple says do not decide
layout by device type. Xcode 27.1 beta is "coming later this month".

**NOT confirmed — only from a third-party blog:** the API names (`onHingeChange`, `UIHingeInteraction`,
`ArrangementView`, `UIArrangementViewController`, `reservedRegion`), how an app opts in to the full
inner screen, and the size class the open screen reports. Less reliable sites give different API
names. The issues say this plainly; verify against the real SDK before writing code.

**Cannot build Duo features yet.** This machine has Xcode 26.6 / iOS 26.5 SDK.

## Traps found this session — read before repeating the work

1. **A search pattern that matches more than you meant gives a false count.** Searching for `.pad`
   also matched every `.padding(`, and reported 35 "iPad checks" when there were 2. It was nearly
   written into the issue as a major finding. Look at a sample of the hits before reporting a count.
2. **The Bash tool runs zsh, not bash.** Two consequences that broke issue filing:
   - an unquoted variable is NOT split on `IFS`, so `for l in $list` loops once over the whole string;
   - `$C:c.md` is read as a zsh modifier (`:c`, `:e`…), not "the value of C followed by :c.md".
   Use `${C}` braces, or write the script to a file and run it with `bash` explicitly.
3. **Apple's design-guidelines page returned only its title** when fetched. Its content is unknown.
