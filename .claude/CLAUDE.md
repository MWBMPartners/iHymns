## 🧱 Modularity rule (non-negotiable)

**When a piece of UI, logic, or data exists in more than one place, extract it into a shared module. If a shared module already exists, reuse it — do not duplicate.**

Concretely, for every platform variant:

- **Web / PWA** (`appWeb/public_html/`) — every `/manage/*.php` page MUST use the shared partials in `appWeb/public_html/manage/includes/` (`admin-nav.php`, `admin-footer.php`, `head-favicon.php`, `auth.php`, `db.php`). Pages MUST NOT inline their own navbar, footer, favicon set, or Bootstrap / Bootstrap-Icons / admin-css loads. New cross-page concerns get a new partial or JS module — not copy-paste into each page.
- **Apple** (`appApple/`) — cross-platform (iOS / iPadOS / tvOS) code lives in shared Swift packages or frameworks. Per-target code lives under its target folder and may only import the shared code, not duplicate it.
- **Android** (`appAndroid/`) — shared UI + domain logic in shared modules (Kotlin Multiplatform where possible; shared Gradle modules otherwise). Per-target code consumes the shared module.
- **Amazon FireOS** — a target of the Android codebase; shares the Android sharedModules, differing only in the launcher / store metadata.

Read throttling on the heavy public reads is `enforceReadRateLimit()` in `includes/read_rate_limit.php` + the additive `tblReadRateLimit` windowed counter (rule #29). The CCLI gate stays: a `ccli`-tier user without a verified live licence is still denied `view_copyrighted`/`play_audio`. Full detail: `project-rules.md §18`.

29. **State-changing AJAX uses `validateCsrfRequest()` (same-origin), not a baked session token** (**#1590**; historically mis-cited as #1352 — see the citation warning in rule #28). `validateCsrfRequest(?string $token)` in `manage/includes/auth.php` is the robust CSRF check for same-origin writes: it accepts the request when EITHER (a) a valid session token was supplied (back-compat with `validateCsrf()`) OR (b) it is a genuine same-origin AJAX request — the custom header `X-Requested-With` is present (a browser cannot set it cross-origin without a CORS preflight this server never grants) AND any present `Origin`/`Referer` host matches `HTTP_HOST` (an explicit cross-origin host is rejected; an absent one is allowed). The `X-Requested-With` route **never goes stale**, which fixes the SPORADIC "CSRF error" on long-lived editor pages (a baked `$_SESSION['csrf_token']` rotates / GCs / changes across multi-tab sessions while the page stays open, so a legitimate merge/delete/save then carries a stale token and is rejected). Wired into `/manage/duplicate-songs` merge/delete, `/manage/places-api.php`, and a top-level POST gate on ALL legacy `/manage/editor/api.php` writes (clients send `X-Requested-With`). The whole-song save moved to the v2 editor API: it is now `editorSaveSongCore()` in `manage/editor/save_song_core.php`, served by BOTH `manage/editor/api.php` (back-compat shim) and `manage/editor/api2.php`, and the editor POSTs the save to api2 under its `X-Requested-With` CSRF gate. New state-changing AJAX endpoints call `validateCsrfRequest()` — never re-bake a per-render session token into a long-lived page and compare it with `validateCsrf()` alone.

30. **An SPA fragment can NEVER carry an executable inline `<script>` — wire it from the router as a real ES module** (#1565/#1568/#1569, 2026-07-26). `index.php` sends an **enforcing** nonce CSP (`script-src 'self' 'nonce-…'`, no `'unsafe-inline'`; #117). Page fragments are served by `api.php` as a **separate HTTP response** that cannot know the document's per-request nonce — and `page=song`/`page=songbook`/`page=home` are in `$_cacheablePages`, so a **shared-cache fragment can never carry a per-request nonce at all** (this is rule #6's constraint applied to scripts). `router.js` used to re-create injected `<script>` nodes via `_executeInlineScripts()`, copying attributes **verbatim** so the re-created node had no nonce either and the browser silently refused it — **console-only violation, no exception, no toast, no visible failure**. This is a SILENT-NO-OP class: the surrounding Bootstrap/markup still works, so the feature *looks* alive and fails only when clicked. It killed the entire public Export feature (all 8 formats, both surfaces) and the Present button for ~7 weeks before a user reported it. **The one correct pattern** is `js/modules/home-page.js` + `router.js`'s `afterPageLoad()`: a real ES module, imported by the router after the fragment lands, with its inputs read DOM-first from `data-*` attributes the fragment already emits (`.page-song[data-song-id]`, `.page-songbook[data-songbook-abbr]`) and the route param only as fallback. NEVER "fix" this by injecting a nonce into fragments, adding `'unsafe-inline'`, or reviving a script-re-creation shim to paper over a missing nonce — all three trade a working CSP for convenience. ⚠️ `_executeInlineScripts()` itself was **deleted in #1619** once nothing needed it — the only `<script>` left in any fragment is an inert `application/ld+json` block in `person.php` — so a fragment `<script>` today simply never runs at all rather than half-running; same dead-on-arrival outcome, more obvious to diagnose. CI guard: `tests/php/test-fragment-inline-scripts.php` fails on any executable nonce-less inline `<script>` under `includes/pages/` or `includes/partials/` (`src=` and `type="application/ld+json"` are exempt; it strips HTML **and** PHP block comments first so `<script>` *mentioned* in a comment doesn't false-positive; the count-exact allowlist is now **empty** — its last entry, `request-a-song.php`, self-cleaned when #1572 extracted that fragment's inline module into a real ES module).

31. **Same-origin requests use `apiFetch()` / `apiFetchJson()` from `js/utils/api-client.js` — NEVER a `window.fetch` override** (#1031). The client attaches cross-cutting request concerns (currently `X-Preferred-Languages`) by STRUCTURE — every call site asks it — not by REPLACING the global `fetch`, which the now-deleted `songbook-language-filter.js` patch did and which failed two ways worth never repeating: (1) a bug in the header logic is not a missing header, it's a FAILED REQUEST surfacing wherever the unrelated caller happens to catch it — #1593 read `input.url` on a `URL` object (`undefined`), called `.startsWith` on it, and threw across ten unrelated call sites, presenting as "Song of the Day disappears when I pick two languages"; (2) a patch only applies if something installed it — `bootSongbookLanguageFilter()` was wired into the router on `home`/`songbooks`/`settings` only, so a cold load of `/search` silently sent no language filter for an anonymous user. `apiFetch` reads the preference on every call, so it cannot be half-installed. Auth headers arrive via an injected provider (`setAuthHeaderProvider()`, wired at boot in `app.js`), not an import, to dodge the `api-client.js` ⇄ `user-auth.js` load-order cycle. The service worker is the one deliberate exception — different global scope, no `localStorage`, requests aren't user-scoped — and keeps native `fetch`.

32. **A fixed-position element injected onto `<body>` outside the SPA's swapped page content must tear itself down on EVERY navigation, as its first statement, before any early return** (#1533). The set-list playback bar moved from an in-flow alert to `position: fixed` on `<body>` so it survives scrolling mid-service — but unlike the in-flow markup it replaced, a fixed element does **not** get removed when `router.js` swaps the page fragment. `SetList.renderSongNavigation()` therefore removes the bar unconditionally before any `return`, and the router calls it on **every** navigation (not just song pages), so leaving a song page cleans up the stranded bar. Putting the render/teardown call only inside the song-page branch, or adding a guard clause ahead of the teardown, both reproduce the bug: the bar strands over whatever page the user goes to next (home, search, …). Any future fixed/sticky global overlay (a banner, a mini-player) follows the same shape.

33. **A URL parameter another page emits is a contract — honour it or stop emitting it** (#1623 → #1628 → #1680, three instances of one shape). A deep-link param the destination does not read is the quietest failure this codebase produces: the page loads, the list populates, Bootstrap works, and the one thing the link asked for never happens. No console error, no toast, nothing to grep. `/manage/revisions` linked `?open=` for its whole life while the editor read only `?song=` — "Open in editor" did nothing for years (#1623). The v2 shell then read `song` and ignored `tab`, so the cutover would have re-broken the very button #1623 had just fixed (#1628). Then it had no `?songbook=`/`#number=` prefill, so the cutover would have killed Missing Numbers' "Open in editor" the same way (#1680). **The method lesson: an API diff finds absent endpoints; a UI diff finds absent screens; NEITHER enumerates the URLs other pages already point at you.** Before changing what a route serves, `grep` for who links to it. `tests/test-editor-deep-links.js` derives those links from the tree and asserts the destination handles each, so a new deep link anywhere is covered automatically. Keep aliases (`?open=` for `?song=`) — they exist precisely because links outlive code. A param aimed at the ROUTER (`?legacy=1`) counts as handled by the router, not the page it redirects to.

34. **A guard must be mutation-tested, and derived from the tree rather than from a list you typed** (the single most repeated lesson of the 2026-07-30 pass). Every hardcoded-list check in this repo has, at some point, passed while the thing it named was broken elsewhere: `test-vendor-sri.js` asserted a great deal about ONE library and stayed green through four pages loading un-hashed Bootstrap across three versions (#1676); the admin-gate audit named five pages and the derived version found eight (#1648). **Derive the list from the tree, then prove the check can fail** — break the thing, watch it go red, restore. Guards written in this pass were wrong-but-green on first run more than once: `test-editor-api2-contract.php` needed its regex window widened from 120 to 300 chars against real source, and `test-editor-deep-links.js` was wrong TWICE (bounding an href on "no quotes or `>`" truncates at an interpolated `?>`; matching params against a whole href misaligns `^`) — each time reporting a confident, incomplete green. **A scanner that under-reports is worse than no scanner, because its tick is read as coverage.** Equally, keep a guard NARROW enough not to fail on correct code: an assertion that banned a phrase outright flagged legitimate user-facing copy, and a guard that fails on correct code gets weakened or deleted rather than fixed.

35. **Cross-file agreement needs a mechanism, not a comment — and HTTP status is the contract, not the error prose** (#1677, #1581, #1627). Whenever two or more files must agree with nothing enforcing it, this codebase breaks: event names (#1581), rate-limit pairs, PHP/JS entitlement maps, npm-vs-CI test lists, the `X-Requested-With` header api2 requires and its own client never sent (#1677), and the `lineTranslations`/`lineAnnotations` payload keys that must match across api2 → `editor2.php` → `enrichment-panel.js`. **A comment saying "keep these in sync" is the failure, not the fix.** Concretely for API clients: `unwrap()` in `manage/editor/v2/api-client.js` attaches `err.status = res.status`, and callers distinguish failure KINDS by **status code** (`409` un-migrated, `422` unprocessable), never by regex-matching the server's sentence. Prose-matching carried a comment reading "if that wording ever changes, update these two together" — reword a server string and the explanatory UI silently degrades to a generic toast with nothing red anywhere. Note too that **documentation is not a mechanism either**: `api-docs.yaml` correctly and publicly documented the `X-Requested-With` requirement for as long as the client was violating it.

36. **Bootstrap CDN tags come from `includes/bootstrap_assets.php` — never typed into a page** (#1676). `ihymns_bootstrap_css_links()` / `ihymns_bootstrap_icons_css_link()` / `ihymns_bootstrap_js_script()` read the pinned URL + SRI from `APP_CONFIG['libraries']['bootstrap']` / `['bootstrap_icons']`. #527 already fixed a version drift by centralising into `head-libs.php`, whose doc-block says the two "can never drift again" — and four pages with a **bespoke `<head>`** (`manage/editor/index.php`, `editor2.php`, `import2.php`, `includes/channel_gate.php`) then ran three different pinned versions, two with no `integrity` at all. The instructive part is WHY they copy-pasted: `head-libs.php` bundles the CDN loads with the theme resolver, three stylesheets, four JS modules and the error monitor, so a page wanting only two `<link>`s could not adopt it without inheriting that whole load order. **The shared thing was too coarse to reuse.** So the reusable unit is the smallest thing that can drift — the tags. When extraction is being ignored, check whether the shared module is too big to adopt before assuming carelessness. `integrity` REQUIRES `crossorigin="anonymous"`; a vendored `onerror` fallback is what makes keeping the hash safe (#1647 ended with somebody deleting an `integrity` attribute to un-break a feature).

37. **Songbook publisher is a REGISTRY (`tblPublishers` family) with the free-text `tblSongbooks.Publisher` kept as a denorm mirror — never a storage merge** (#93 / epic #1765). The publisher was a free-text column; #93 promotes it to a first-class registry of persons AND companies (`tblPublishers` — `Kind` VARCHAR vocab; optional `MusicianId` FK so a musician-publisher isn't duplicated; `ParentId` self-FK for imprint / **catalogue grouping**; `Ipi`/`Isni` NULL-distinct UNIQUE; `CityName`+`CityId` place mirror; `IsActive`), a multi-publisher M:N (`tblSongbookPublishers` — mirrors `tblSongbookCompilers`; `Role` VARCHAR vocab; `uq_book_pub_role` allows one publisher in several roles but never the same role twice; dormant `ValidFrom`/`ValidTo`), and the forward-looking `tblPublisherAliases` + `tblPublisherExternalLinks` (rule #15/#20 one-pass). `tblSongbooks.Publisher` STAYS as a JOIN-free denorm display mirror (same pattern as `TuneName↔TuneId`) — the editor multi-publisher picker re-syncs it to the **primary (first-listed)** publisher on save; an empty picker leaves the typed value. **The ONE shared core** is `includes/publisher_admin.php` (validate/uniqueness/persist/create/rename-cascade/aliases/usage/delete/merge) + `includes/publisher_helpers.php` (`IHYMNS_PUBLISHER_KINDS`/`IHYMNS_PUBLISHER_ROLES` VARCHAR vocabs, slug fold, `publisherFindOrCreateByName()`); `/manage/publishers` and the future `admin_publisher_*` API both delegate to it (rule #22). `manage_publishers` entitlement. Public page `/publisher/<slug>` (`includes/pages/publisher.php`, `?page=publisher&slug=…`) resolves exact-slug → name-fold → alias-fold (rule #33 — the admin list + editor picker emit the link). Backfill: `migrate-publishers-entity.php` from DISTINCT `Publisher` strings, **idempotent by Name existence, not slug** (no `uq_Name` — two publishers may share a name under different Disambiguation, so INSERT-IGNORE-on-slug would mint duplicates on re-run). Never re-fork the publisher CRUD, never hardcode a Kind/Role list, never make `tblSongbooks.Publisher` authoritative over the registry, and never emit a `/publisher/` link without the page resolving it. CI guard: `tests/php/test-publisher-registry.php`.

### Red flags during review

Reject any change that introduces:

- A duplicate `<nav>` on an admin page.
- A duplicate `<link rel="stylesheet" href="/css/app.css">` + `/css/admin.css` block when `admin-footer.php` or another shared include could host it.
- A hard-coded list of roles, entitlements, licence types, tier names, or card IDs that already exists in a central map.
- A PDO / mysqli instantiation outside `getDbMysqli()`. (PDO is no longer used at all — any `new PDO(...)` is a regression.)
- A `<script>` loading Bootstrap or Bootstrap-Icons on a page that also includes `admin-footer.php` (double-load).
- An inline click handler that re-implements behaviour the corresponding shared JS module already offers.
- A hand-rolled regex / `URL.hostname.endsWith(...)` ladder for "what kind of link is this" — `external-link-detect.js` already exists and reads its rules from `tblExternalLinkPatterns`.
- A new admin list page that doesn't opt into `.admin-table-responsive` + sortable headers (#842 / #844) when surrounding pages already do.
- A duplicate songbook/song/credit-person/work "external links" editor — reuse the shared chip-list module, don't fork it per entity.
- A second copy of the duplicate/counterpart similarity maths (normalise / levenshtein / Jaccard / blend). `includes/song_similarity.php` (#1216) is the **one** scorer — the batch builder, the `/manage/duplicate-songs` review page and the editor's inline panel all consume it. Re-forking it (as the builder's old `_bsls_*` did) is the regression #1216 removed. Likewise, never reintroduce a standalone `/manage/song-link-suggestions` page — that workflow was unified into `/manage/duplicate-songs` (#1215).
- A new admin page that hardcodes `<html lang="en" data-bs-theme="dark">`. The theme is resolved at runtime by `admin-theme-init.php` (#955) reading the user's preference from `localStorage`. Hardcoding the attribute causes a flash of dark for users who picked Light / High-contrast / System with light OS.
- A read-side endpoint that materialises the WHOLE corpus (the old `SongData::exportAsJson()` / `songsCacheServe()` pattern — both removed in WS-J #1020). Reads MUST be scoped: `getSongsSlimIndex()` (lightweight index), `getSongs($abbr)` (one songbook), or `getSongById()` (one record). Reintroducing a whole-corpus load (~140 MB of PHP-array memory, #929 OOM) or a server-side `songs.json` cache is a regression.
- A prose link styled `text-decoration: underline; color: blue;` or via `<a style="color: var(--bs-link-color)">`. The global `<a>` default in `app.css` Section 2.5 (#951) handles muted styling site-wide; explicit colour-blue overrides revive the Bootstrap default we deliberately killed.
- A new `migrate-*.php` script that creates a table or adds a column but doesn't update `appWeb/.sql/schema.sql` in the same commit. CI's `test-schema-coverage.php` will fail; that's the signal — copy the CREATE TABLE / column declaration into schema.sql alongside the migration.
- A new entry in `$migrationOrder` (in `manage/setup-database.php`) without a matching probe in `$migrationProbes`, OR a probe written as `static fn(\mysqli $db) => true`. Both make the dashboard's pending counter stuck above zero. CI's `test-migration-registry.php` will fail; the probe must check the live schema / data (or a `tblAppSettings` sentinel the migration writes) so the card flips from pending → applied once the work has landed.
- An `ENUM` column for any vocabulary that could grow (moderation states, kinds, signals, types). Use `VARCHAR` + an app-level allow-list — an ENUM value-add is an `ALTER` (rule #20). Existing ENUMs (e.g. `tblLyrics.Status`) are grandfathered; new ones in the #1066/#1088 families are deliberately VARCHAR.
- Per-line translations or annotations stored as a JSON parallel array on `tblSongComponents`, or anchored on a `LinesJson` index. They belong in `tblLyricLineTranslations` / `tblLyricLineAnnotations` anchored on `tblLyricLines.Id` (rule #21). Slicing a line by byte or UTF-16 offset instead of code point is also a regression.
- An incremental `ALTER` that re-opens a schema family already shipped one-pass (#1066/#1088), when the column/table could have been included in the original forward-looking batch. Prefer extending the dormant table; only ALTER for genuinely unforeseeable needs.
- A songbook list / grid that filters out `IsOfficial = 0` books, or a hand-rolled "unofficial" label instead of the shared `.songbook-unofficial-badge` (#1223). Unofficial books are first-class-but-badged; the one badge class is reused on the home tiles, `/songbooks` and the songbook header.
- Renaming `tblCatalogues` / the `/manage/catalogues` route / the `'catalogue'` entity type / `admin.catalogues.*` keys to "collection" (#1223). The Catalogue→Collection change is **user-facing copy only** — the internal identifiers stay `catalogue`.
- A hard-coded theme / tag list, or re-seeding theme vocabulary ad-hoc instead of via `migrate-seed-theme-vocabulary.php` + the `/manage/tags` canonicalisation merge (#1152 / #1222).
- A page or handler that treats `$db->query(...)` / `$db->prepare(...)` as returning **`false`** on error (e.g. `if ($res = $db->query(...))` as the only guard). The DB layer runs mysqli under `MYSQLI_REPORT_ERROR | MYSQLI_REPORT_STRICT` (`includes/db_mysql.php`), so a failing statement **throws** `mysqli_sql_exception`; the false-check is dead code and an uncaught throw white-screens the page. Existence-probe optional tables/columns (INFORMATION_SCHEMA) and wrap page-load detection in `try/catch` → themed error card. Migrations are NOT auto-applied on deploy, so "it's in `schema.sql`" ≠ "it exists on alpha". This blanked `/manage/duplicate-songs` (#1228 → fixed #1229); detail in `project-rules.md §9`.
- A second lyric-line reader or writer, or an UNGATED `tblSongComponents.LinesJson`/`ChordsJson`/`NotesJson`/`LanguagesJson` reference (#1235 P4, rule #25). Lines are read ONLY via the `includes/lyric_lines_read.php` assembler and written ONLY via `lyricLinesWriteComponents()`; a raw doomed-column SELECT/INSERT/UPDATE outside a `lyricLinesMirrorPresent`/`lyricLinesSyncReady`/`lyricLinesComponentsLangReady`/`INFORMATION_SCHEMA`/`columnExists` gate or a marked `lines-json-fallback` branch will throw under STRICT once the C6 drop runs — `tests/php/test-component-json-guard.php` fails on it. Never reintroduce `LinesJson` as the authoritative source, never store per-line translations/annotations on a JSON parallel array (rule #21), and never auto-run the destructive `retire-component-lines-json` drop (it is `'manual'` + `confirm=1`-gated).
- A re-forked tier→capability matrix, or a new gating cap added as a `tblAccessTiers` **column** or a hardcoded per-tier `['public' => [...], 'free' => [...]]` map (#1352/#1353, rule #28). `TIER_CAPS` in `includes/access_tier_validation.php` is the ONE registry; a new cap is ONE `'json'` line + its migration card, never a new column and never a second matrix. The `$tiers` map inside `checkTierAccess()` survives ONLY as the un-migrated/unknown-tier fallback — overlaying a new matrix on top of it (instead of registering a cap) is the regression. Likewise an enforcement path that hardcodes its own tier→field decisions instead of asking `checkTierAccess()` (the registry-backed resolver), or a `content_gating.php` change that isn't a verified no-op when `content_gating_enabled='0'`, is a regression (rule #28 A/B).
- A state-changing AJAX endpoint that compares a per-render baked `$_SESSION['csrf_token']` with `validateCsrf()` ALONE on a long-lived page (#1352, rule #29). That token goes stale (rotates / GCs / changes across tabs) and produces the SPORADIC "CSRF error" on merge/delete/save. Use `validateCsrfRequest()` (same-origin: `X-Requested-With` + `Origin`/`Referer` host match, OR a still-valid session token) instead. Re-implementing a bespoke same-origin check inline instead of calling the shared helper is also a regression.
- An executable inline `<script>` in an `includes/pages/*.php` or `includes/partials/*.php` fragment (#1565, rule #30). The enforcing nonce CSP refuses it and the failure is **completely silent** — the feature looks alive and only dies on click. Wire it as a real ES module imported from `router.js`'s `afterPageLoad()` (the `home-page.js` pattern), reading its inputs from `data-*` on the fragment. `tests/php/test-fragment-inline-scripts.php` fails the build on this. Equally a regression: "fixing" it by injecting a nonce into a shared-cache fragment, adding `'unsafe-inline'` to the CSP, or reviving a script-re-creation shim (the deleted `_executeInlineScripts()`, removed #1619) to re-stamp a nonce.
- A raw `ihymns:*` / `iHymns:*` DOM event-name literal outside `js/constants.js` (#1581). Event names live once in `constants.js`; `tests/test-event-names.js` bans raw literals and asserts every name has both a dispatcher and a listener. The regression class is the Settings language filter, which dispatched one spelling while Song of the Day listened for another — a silent no-op with no error, exactly like rule #30's failure mode.
- A CDN `<script>` / `<link>` on an admin page with a **floating** version tag (`@5`, `@latest`) or no `integrity` attribute (#1587). Third-party code inside an authenticated admin session must be pinned exactly, SRI-checked, vendored by `tools/download-vendor.sh`, and fall back to `/vendor/…` — the `APP_CONFIG['libraries']` registry in `includes/config.php` is where the version, hash and local path live. Equally a regression: an asset-load failure whose only symptom is `console.error` (there is no client error monitor under `/manage/*`, so the admin just sees a blank pane).
- An admin page whose own gate differs from the entitlement its nav entry advertises in `admin-links.php` (#1587). The two must be the same check, or a role that clears one but not the other can either deep-link past the menu or follow a menu link straight into a 403.
- A browser `fetch()` of a static asset using a **relative** URL from code that can run on more than one route (#1566). `fetch()` resolves against the DOCUMENT, not the script — and this SPA's `.htaccess` catch-all answers any unmatched path with **HTTP 200 + the HTML shell**, so `response.ok` passes and the failure surfaces as a baffling `SyntaxError` inside `.json()` rather than a 404. Use a root-absolute path (`/manage/editor/protos/proto-bundle.json`), as the rest of the codebase does.
- A new `window.fetch` override, or a module reaching for bare `fetch()` when it needs a cross-cutting request concern honoured (#1031, rule #31). Import `apiFetch` / `apiFetchJson` from `js/utils/api-client.js` instead — a global patch only fires if something installed it (the deleted language-filter patch silently skipped `/search` for anonymous users) and a bug in it fails the REQUEST, not just the feature, for every caller site-wide.
- A change to what a route SERVES (or a new page that consumes deep links) without first `grep`ping who links to it (#1680, rule #33). A URL param the destination doesn't read fails silently — the page loads and the instruction is simply lost. `tests/test-editor-deep-links.js` derives the links from the tree; if a new entry point is added, it must be handled or not emitted. Dropping an alias like `?open=` is the same regression: those exist because links outlive code.
- A new CI guard that hardcodes the list of things it checks, or that was never proven able to fail (rule #34). Derive the list from the tree, then break the thing and watch it go red. A guard whose first green run was never challenged has, in this repo's history, repeatedly been silently wrong — including several written in the same pass as this rule. Equally a red flag: a guard so blunt it fails on correct code (banning a phrase that legitimate user-facing copy contains), because that gets it weakened or deleted rather than fixed.
- A client that distinguishes API failure KINDS by regex-matching the server's error sentence rather than the HTTP status (#1677, rule #35). `unwrap()` attaches `err.status`; branch on `409`/`422`. Any comment of the form "if that wording ever changes, update these two together" marks a missing mechanism — as does relying on documentation to hold two files in agreement (`api-docs.yaml` documented the `X-Requested-With` contract correctly throughout the period its own client violated it).
- A hardcoded CDN `<script>`/`<link>` for Bootstrap or Bootstrap-Icons anywhere, including on a page with a bespoke `<head>` (#1676, rule #36). Call `ihymns_bootstrap_css_links()` / `ihymns_bootstrap_icons_css_link()` / `ihymns_bootstrap_js_script()`. `integrity` without `crossorigin="anonymous"` is also a regression — the browser then cannot read the body to hash it and refuses the file outright, which is how an SRI attempt becomes a dead stylesheet.
- A fixed/sticky global UI element (a bar, banner, mini-player) whose render function doesn't unconditionally remove the existing instance as its very first statement, or that only gets called from one page's branch instead of the router's every-navigation hook (#1533, rule #32). Unlike in-flow markup, a `position: fixed` element on `<body>` survives an SPA content swap on its own — skip the teardown-before-any-return ordering and it strands over whatever page the user navigates to next.
- A re-forked publisher CRUD, a hardcoded publisher Kind/Role list, or a new gateable publisher concern added as anything other than a `tblPublishers`-family row (#93, rule #37). `includes/publisher_admin.php` + `includes/publisher_helpers.php` are the ONE cores; the vocabularies live in `IHYMNS_PUBLISHER_KINDS`/`IHYMNS_PUBLISHER_ROLES` (VARCHAR, not ENUM). Also a regression: making `tblSongbooks.Publisher` authoritative over the registry (it's a denorm mirror synced from the primary registry publisher), a publisher-backfill deduped by slug instead of Name existence (it would mint `name-2` duplicates on re-run — there is deliberately no `uq_Name`), or emitting a `/publisher/<slug>` link the destination can't resolve (rule #33 — the page's exact-slug→name-fold→alias-fold ladder is the contract).

When in doubt: extract first, use second. A 30-line partial is cheaper than debugging five divergent copies.

## 🛠 Commit / PR expectations

- **One PR per piece of work, multiple commits inside it.** Group related work into a single PR with logical, well-scoped commits rather than splitting across several smaller PRs. One review session, one deploy to alpha, one verify pass. Each commit stays atomic and individually revertable (`git revert <sha>` works per-commit). Avoids the inter-PR race conditions and multi-deploy churn that bit the 2026-04-25 audit-cleanup work, where a chain of small PRs each triggered its own deploy + verify cycle and one mis-diagnosis cascaded through all of them. Multiple PRs only for genuinely independent pieces of work that happen to be in flight at the same time (e.g. unrelated bugfix + unrelated feature).
- Commits have descriptive first-line summaries; wrapped body explaining the WHY, not just the WHAT.
- Every user-reported bug or feature gets a tracking GitHub issue **before** the commit that closes it, so the timeline reads sensibly.
- PRs target `alpha`. Stacked PRs (PR-B depends on PR-A landing first) are an exception, reserved for genuinely sequential dependencies — most work should land as a single PR per the rule above. Note the base branch in the description.
- Never skip pre-commit hooks (`--no-verify`), never force-push main/alpha, never amend merged commits.
- Audit before opening a PR: PHP syntax (`find appWeb -name '*.php' -exec php -l {} \;`), JS syntax (`find appWeb -name '*.js' -exec node --check {} \;`), security + accessibility + structure per the pattern established on PR #445.

## 🙋 Asking the owner for a decision (owner-stated, 2026-07-30)

**Never surface a bare question.** Whenever work stops on an owner decision — in chat, in a handoff,
or in a GitHub issue — present it in this shape every time:

1. **The decision** — what is actually being chosen between, in one sentence, in plain language.
2. **Why it needs deciding** — what makes it a judgement call rather than something to work out from
   the code. Usually one of: a product question, a data-shape consequence, or a plan you cannot see.
3. **The options** — each with its real consequence, including the cost of doing nothing. A table is
   usually the clearest form.
4. **A recommendation, always** — say which one you would pick **and why**. "It's up to you" is not
   an answer; the owner is asking because they want a considered view, not a menu.
5. **What you need back** — the smallest possible reply that unblocks you ("A, B or C", "confirm the
   number"). Make it answerable in a sentence.

Also state plainly whether the decision **blocks** anything. Most do not, and saying so lets the
owner defer without worrying they are holding up a branch.

If a decision has a **sub-question the owner did not answer**, pick the defensible default, say so
explicitly, and flag it as trivially changeable — do not stall the whole item on a detail.

The three worked examples are #1661, #1668 and #1671. `#1679` is the worked example of the follow-up
obligation: **if further investigation undermines your own recommendation, say so unprompted and
explain what changed** — there, machinery already existed that made the option I had argued against
much cheaper than I claimed.

Raw session transcripts live at `~/.claude/projects/<project-hash>/*.jsonl` on whichever device Claude Code ran — they contain the full tool-call log (every file read, every command run, every response). The repo carries **scrubbed copies** in `.claude/sessions/`, synced via:

```
tools/sync-claude-session.sh
git diff .claude/sessions/    # REVIEW — scrubber is best-effort
git add .claude/sessions/ && git commit -m "chore(sessions): sync"
```

The scrubber redacts known token shapes (Anthropic, GitHub, AWS, Google, `Bearer`, private keys). It does **not** catch a password typed into a prompt or customer data in a test fixture. Always review the diff. See `.claude/sessions/README.md` for the full policy.

Per-user global memory (`~/.claude/CLAUDE.md`) stays on the user's machine — it's not project policy. If guidance from a session turns out to be permanent, copy it into `.claude/project-rules.md` here so future sessions pick it up automatically.
